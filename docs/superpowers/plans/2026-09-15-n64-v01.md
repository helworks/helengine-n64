# N64 v0.1 Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` to implement this plan task by task. Intended implementer: **gpt-5.6-luna, xhigh**, sequentially in one session. No subagents or independent review are authorized by this document.

**Goal:** Produce a standalone N64 ROM with working video and a rotating, unlit, face-colored cube.

**Architecture:** A small entry point delegates to a native boot host, video owner, and Tiny3D renderer. Complete one graphics frame before changing mutable matrices or viewport data. Keep the original cube geometry resident throughout execution.

**Tech stack:** C++17, libdragon preview, Tiny3D, GNU Make, Docker Linux builds, PowerShell entry points, ares Homebrew mode.

**Spec:** [N64 v0.1 design](../specs/2026-09-15-n64-v01-design.md). Read it and both original reference documents before implementation.

## Global constraints

- Native host and cube only. No generated runtime, editor, C# builder, scene export, audio, filesystem, textures, or input-service implementation.
- 320 × 240, 16-bit color, two display buffers, one 16-bit depth surface, base 4 MiB support.
- Six opaque face colors; no lighting, textures, fog, or blending. Normal rendering enables backface culling and depth testing/writing.
- Elapsed-time rotation; cap one update at 100 ms. No application allocation in the frame loop.
- Preserve Tiny3D clipping and SDK cache/alignment contracts. Wait for graphics completion once per frame.
- Keep artifacts, SDK checkouts, logs, and emulator profiles out of Git. Do not modify sibling ports or global tool configuration.
- Record build, emulator, and hardware evidence separately. No screenshots of the user's desktop/windows without permission.
- Read applicable AGENTS.md files. Preserve unrelated changes. Commit passing checkpoints locally; do not push.

Shared contracts below belong to separate classes, not one common header:

```cpp
// Nintendo64BootHost
int Run();
// Nintendo64Video
bool Initialize();
void BeginFrame(); // acquire and attach color/depth
void Clear();      // after Tiny3D frame setup
void EndFrame();   // complete and present
void Shutdown();  // after renderer shutdown
// Nintendo64CubeMesh
bool Initialize();
const T3DVertPacked* GetVertices() const;
const uint8_t* GetIndices() const; // 36 entries, 24 logical vertices
void Shutdown();
// Nintendo64RasterRenderer owns mesh, viewport, and fixed-point model matrix.
bool Initialize();
void Prepare(float angleX, float angleY); // previous frame must be complete
void BeginScene();
void DrawCube(bool reverseOrder, bool disableCullingForDepthProbe);
void Shutdown();
// Nintendo64FrameClock; uint64_t timestamps are microseconds.
void Reset(uint64_t nowUs);
void Advance(uint64_t nowUs);
float GetAngleX() const;
float GetAngleY() const;
```

// Initialize
 display_init(RESOLUTION_320x240, DEPTH_16_BPP, 2,
              GAMMA_NONE, FILTERS_RESAMPLE);

// BeginFrame

// Clear

## Task 2 — Static unlit cube

**Files:** mesh and renderer pairs; modify host, Makefile, validation record.

**Consumes:** video lifecycle. **Produces:** a fixed-pose cube and renderer contract.

- [ ] Allocate 12 `T3DVertPacked` records (two vertices each) and one `T3DMat4FP` using `malloc_uncached`. Check allocations, zero unused normal/UV fields, and use `free_uncached` after completion at shutdown. Keep immutable CPU indices; triangle calls copy index values.
- [ ] Build the cube from the outward-wound face quads below. For face base `b=face*4`, emit triangles `(b,b+1,b+2)` and `(b,b+2,b+3)`. Validate 24 logical vertices, 36 indices `<24`, nondegenerate triangles, and outward cross products in initialization diagnostics.

| Face | v0 | v1 | v2 | v3 | RGBA |
|---|---|---|---|---|---|
| +X | (4,-4,-4) | (4,4,-4) | (4,4,4) | (4,-4,4) | `0xFF4040FF` |
| -X | (-4,-4,4) | (-4,4,4) | (-4,4,-4) | (-4,-4,-4) | `0x40FFFFFF` |
| +Y | (-4,4,-4) | (-4,4,4) | (4,4,4) | (4,4,-4) | `0x40FF40FF` |
| -Y | (-4,-4,4) | (-4,-4,-4) | (4,-4,-4) | (4,-4,4) | `0xFF40FFFF` |
| +Z | (-4,-4,4) | (4,-4,4) | (4,4,4) | (-4,4,4) | `0x4040FFFF` |
| -Z | (4,-4,-4) | (-4,-4,-4) | (-4,4,-4) | (4,4,-4) | `0xFFFF40FF` |

- [ ] Call `t3d_init(T3DInitParams{})`, create a persistent viewport using `t3d_viewport_create()`, and use camera `(0,0,-18)`, target origin, up `(0,1,0)`, vertical FOV 60 degrees, near 1, far 100. Set X=0.35 and Y=0.55 radians for the fixed pose.
- [ ] `Prepare` creates rotations with pinned `fm_mat4_t` helpers, composes **Y × X**, then calls `t3d_mat4_to_fixed`. Check multiplication argument order in the installed header; do not assume another math library's convention. Previous frame completion must precede this update.
- [ ] `BeginScene` calls `t3d_frame_start()` then `t3d_viewport_attach(&Viewport)`. Host clears next. Apply this drawing state afterward, since frame start resets AA:

```cpp
rdpq_mode_combiner(RDPQ_COMBINER_SHADE);
rdpq_mode_antialias(AA_NONE);
rdpq_mode_zbuf(true, true);
rdpq_mode_blender(0);
rdpq_mode_fog(0);
t3d_light_set_count(0);
uint32_t flags = T3D_FLAG_SHADED | T3D_FLAG_DEPTH | T3D_FLAG_NO_LIGHT;
if (!disableCullingForDepthProbe) flags |= T3D_FLAG_CULL_BACK;
t3d_state_set_drawflags(static_cast<T3DDrawFlags>(flags));
t3d_matrix_push(ModelMatrix);
t3d_vert_load(Mesh.GetVertices(), 0, 24);
t3d_matrix_pop(1);
const uint8_t* indices = Mesh.GetIndices();
for (int draw = 0; draw < 12; ++draw) {
    const int triangle = reverseOrder ? 11 - draw : draw;
    const int offset = triangle * 3;
    t3d_tri_draw(indices[offset], indices[offset+1], indices[offset+2]);
}
t3d_tri_sync();
```

`ModelMatrix`, `Mesh`, and `Viewport` are persistent renderer members. No retained display-list block is necessary for 12 triangles. Zero directional lights alone is insufficient: keep the explicit NO_LIGHT flag.

- [ ] Wire the host in this order:

```cpp
Renderer.Prepare(0.35f, 0.55f);
Video.BeginFrame();
Renderer.BeginScene();
Video.Clear();
Renderer.DrawCube(false, false);
Video.EndFrame();
```

- [ ] In diagnostic builds, call `rdpq_debug_start()` after RDPQ initialization. Verify identity and rotated poses, expected face colors, and actual winding/culling convention. Keep the geometric winding table fixed while investigating a view-convention mismatch.
- [ ] Run a depth probe with **culling disabled**, in normal and reversed triangle order. Both must show the same exterior surfaces. A backface-culled convex cube is a weak depth test because its visible faces rarely overlap. Restore culling for the normal scene.

**Acceptance:** correct static image and face colors, order-independent depth probe, no RDPQ validation errors.

**Checkpoint commit:** `feat(n64): render a static unlit cube`.

## Task 3 — Time-based rotation and stability

**Files:** frame-clock pair, host tests, host-test script; modify host/Makefile and validation record.

**Consumes:** verified static renderer. **Produces:** stable animated cube and tested clock behavior.

- [ ] Write these tests for the actual clock before implementing its behavior. Reset initializes X=0.35, Y=0.55. Speeds: X=0.35 rad/s, Y=0.60 rad/s. Clamp delta at 100,000 us; backward timestamps contribute zero and replace the previous timestamp. Wrap at 2π.

```cpp
#include <cassert>
#include <cmath>
#include "platform/n64/Nintendo64FrameClock.hpp"
using helengine::n64::Nintendo64FrameClock;
int main() {
    Nintendo64FrameClock a, b;
    a.Reset(0); b.Reset(0);
    for (uint64_t i=1; i<=50; ++i) a.Advance(i*1000000/50);
    for (uint64_t i=1; i<=60; ++i) b.Advance(i*1000000/60);
    assert(std::fabs(a.GetAngleX()-0.70f)<0.0001f);
    assert(std::fabs(a.GetAngleY()-1.15f)<0.0001f);
    assert(std::fabs(a.GetAngleY()-b.GetAngleY())<0.0001f);
    Nintendo64FrameClock paused;
    paused.Reset(0); paused.Advance(5000000);
    assert(std::fabs(paused.GetAngleY()-0.61f)<0.0001f);
    paused.Advance(5020000);
    assert(std::fabs(paused.GetAngleY()-0.622f)<0.0001f);
    paused.Advance(5010000);
    assert(std::fabs(paused.GetAngleY()-0.622f)<0.0001f);
    for (uint64_t i=1; i<=10000; ++i) a.Advance(1000000+i*20000);
    assert(a.GetAngleX()>=0 && a.GetAngleX()<6.283186f);
    assert(a.GetAngleY()>=0 && a.GetAngleY()<6.283186f);
}
```

- [ ] `scripts/test-host.ps1` compiles/runs with the container's native g++, propagating failure. Create `build/` first and retain the initial failing result, then the passing result:

- [ ] Implement Advance with integer timestamp subtraction before float conversion:

```cpp
uint64_t deltaUs = nowUs >= PreviousUs ? nowUs - PreviousUs : 0;
PreviousUs = nowUs;
if (deltaUs > 100000) deltaUs = 100000;
const float seconds = static_cast<float>(deltaUs) * 0.000001f;
AngleX = std::fmod(AngleX + seconds * 0.35f, 6.28318530718f);
AngleY = std::fmod(AngleY + seconds * 0.60f, 6.28318530718f);
```

PreviousUs, AngleX, AngleY are members initialized by Reset; getters return their values. Document Reset-before-Advance. Pass tests, then call Reset/Advance with `get_ticks_us()` in the host and supply the angles to Prepare.

- [ ] Keep EndFrame blocking before the next update. Do not infer matrix safety from double buffering. Keep viewport storage alive through the entire run.
- [ ] Add compile-time diagnostic poses: normal rotation; identity cube with camera `(0,0,-4.5)` so the near plane cuts its front; identity cube translated X=-12 then X=12 to cross viewport edges. Preserve the normal clipping path. No input subsystem is needed to choose a diagnostic build.
- [ ] Run ten minutes in ares, checking for flicker, corruption, or hangs. Emit a bounded heartbeat at most once per minute with completed-frame count and angles. Review application allocations and SDK lazy paths after warmup. If a supported memory counter exists, record its results; otherwise do not describe allocation review as a measured leak test.
- [ ] Exercise PAL/NTSC when available and verify the same angular speed. Clock tests validate arithmetic, not actual VI compatibility. Verify bounded advance after a debugger pause.

**Acceptance:** host tests pass, stable animation and clipping, honest TV-mode and memory evidence, no premature resource reuse.
